# 밥찰칵 설계·기획서 (v0.1 초안)

## 1. 한 줄 정의
> 먹을 때 사진을 찍으면 시간과 함께 저장되고, 달력·날짜·전체 타임라인으로 돌아볼 수 있는 앱.

### 하지 않는 것 (원칙)
칼로리/영양 분석, 식단 조언, 목표·알림 압박, 계정/로그인, 소셜 공유, 광고, 서버 전송.
→ **기록하는 데 필요한 것만 넣는다. 탭 수가 늘어나는 기능은 넣지 않는다.**

## 2. 핵심 화면 (3개 + 뷰어)
| 화면 | 내용 |
|---|---|
| **달력** (홈) | 월 달력. 각 날짜 칸에 식사 횟수(점 또는 숫자). 날짜 탭 → 그 날 화면 |
| **하루** | 선택한 날의 사진을 시간순 목록으로. 시각 표시(예: 08:12). 사진 탭 → 뷰어 |
| **타임라인** | 전체 기록을 메신저 대화방처럼 한 줄로 쭉 스크롤 (날짜 구분선 포함, 아래가 최신). 달력에서 날짜로 점프 가능 |
| **사진 뷰어** | 전체 화면. **좌우 스와이프로 전체 기록 순서대로** 넘김. 시각 표시. 삭제/시간수정 |
| **촬영 버튼** | 모든 화면 하단 고정 큰 버튼 하나. 누르면 바로 카메라 → 찍으면 즉시 저장(확인 단계 없음) |

핵심 UX: **앱 열기 → 버튼 → 촬영 → 끝 (3탭 이내, 이상적으로 2탭).**
앱을 열면 카메라가 바로 뜨는 옵션도 설정으로 제공(선택).

## 3. 꼭 필요한 최소 기능 (질문에 대한 답)
"사진+시간 저장, 달력, 날짜별, 전체 슬라이드" 외에 **빠지면 실제로 곤란해지는 것**만 추렸습니다.

### A. 반드시 (v1 포함)
1. **백업 / 복원** — 이 앱의 가장 중요한 부가 기능 (아래 §5)
2. **저장소 영구 보존 요청** — `navigator.storage.persist()`. 브라우저가 공간 부족 시 데이터를 지우는 것 방지
3. **삭제** — 잘못 찍은 사진 지우기 (뷰어에서 길게 누르기/버튼 + 확인)
4. **시간 수정** — 먹고 나서 깜빡하고 나중에 찍었거나, 과거 사진을 넣을 때 필요
5. **갤러리에서 추가** — 이미 찍어둔 사진을 가져오되 시각은 사진 촬영시각(EXIF/파일 수정일)으로
6. **사진 용량 자동 축소** — 원본(3~8MB)을 그대로 저장하면 1년 뒤 수 GB. 긴 변 1280px / JPEG 품질 0.8 → 장당 약 150~300KB
7. **오프라인 동작** — 전부 기기 안에서만 동작, 네트워크 불필요
8. **시간대/날짜 경계 처리** — "하루"는 기기 로컬 날짜 기준. 새벽 야식은 그 날짜로 보되, 설정에서 *하루 시작 시각*(예: 04:00)을 바꿀 수 있게 (v1.1 후보)
9. **빈 상태 / 카메라 권한 거부 안내** — 한 줄 안내만

### B. 있으면 좋음 (v1.1 이후, 필요할 때만)
- 사진 한 줄 메모 (기본 숨김, 쓰고 싶을 때만)
- 앱 잠금(PIN/생체) — 사진이 사적이라면
- 사진 1장을 갤러리로 저장/내보내기
- 저장 공간 사용량 표시 (설정 화면에 한 줄)
- 백업 N일 경과 시 부드러운 알림 배너 (팝업 아님)
- 다크 모드

### C. 의도적으로 안 넣음
통계 그래프, 식사 종류 태그(아침/점심/저녁 분류), 칼로리, 검색, 공유, 클라우드 계정, 알림 푸시.
(시간만 있으면 아침/점심/저녁은 사진 시각으로 알 수 있으므로 분류 입력은 불필요)

## 4. 기술 선택 (권장안)
**권장: PWA (설치형 웹앱), 프레임워크·빌드 없이 순수 HTML/JS(ES modules)**

| 선택지 | 장점 | 단점 |
|---|---|---|
| **PWA (권장)** | 기존 `하루 한발짝`과 같은 방식·같은 GitHub Pages 배포, 설치/스토어 심사 없음, 가벼움 | iOS에서 저장소 정책이 보수적 → **백업이 필수**, 갤러리 직접 저장 제한 |
| Flutter/React Native | 파일/갤러리 접근 자유, 네이티브 느낌 | 빌드·서명·스토어 필요, 무거움 |
| Capacitor로 PWA 포장 | PWA 코드 재사용 + 네이티브 저장소 | 나중에 필요하면 추가 가능 (후순위) |

→ PWA로 시작하고, 저장소 안정성이 문제되면 Capacitor로 감싸는 경로를 열어둡니다.

### 카메라
- 1순위: `<input type="file" accept="image/*" capture="environment">` — 가장 호환성 높고 OS 카메라 앱 품질 그대로
- 대안: `getUserMedia` 인앱 라이브 뷰 (한 번 탭으로 촬영하는 속도가 필요하면)

## 5. 저장소·데이터 설계
### 저장 위치
**IndexedDB** (기기 내부, 서버 없음). 사진은 Blob으로 저장.

### 스키마 (`meals` 스토어)
```
id         string   ULID/UUID (시간 정렬 가능, 백업 병합 시 중복 판별)
takenAt    number   촬영 시각 (epoch ms)
tzOffset   number   당시 UTC 오프셋(분) — 해외여행 시에도 "그때 현지 시각" 복원
dateKey    string   'YYYY-MM-DD' 로컬 날짜 (달력 조회용 인덱스)
photo      Blob     축소된 JPEG (긴 변 1280px)
thumb      Blob     썸네일 JPEG (긴 변 320px) — 달력/목록 속도용
note       string?  (v1.1) 메모
createdAt  number   기록 생성 시각
```
인덱스: `takenAt`, `dateKey`.
`settings` 스토어: 하루 시작 시각, 마지막 백업 시각 등 키-값.

### 용량 추정
하루 5장 × 약 200KB ≈ 1MB/일 → **연 약 350MB**. 기기 저장엔 문제 없지만, 아래 백업은 이를 고려해 설계.

## 6. 백업 / 복원 설계
**원칙: 백업 파일은 앱 없이도 열어볼 수 있어야 한다.**

- **형식**: ZIP 하나
  ```
  mealsnap-backup-2026-10-15.zip
  ├─ meta.json          # [{id, takenAt, tzOffset, file}, ...] + 버전
  └─ photos/
     ├─ 01J....jpg      # 파일명 = id
     └─ ...
  ```
  JPEG는 이미 압축돼 있으므로 ZIP은 무압축(store) 방식으로 직접 작성 (외부 라이브러리 불필요, 약 60줄).
- **내보내기**: 설정 → "백업 만들기" → 공유 시트(Web Share API)로 Drive/iCloud/파일에 저장. 미지원 시 다운로드.
- **큰 데이터 대응**: 메모리 한계(수백 MB) 때문에 **월 단위 분할 백업** 옵션 (`mealsnap-2026-10.zip`) 제공 → "마지막 백업 이후 추가분만" 증분 백업도 가능.
- **복원**: 백업 ZIP 선택 → `id` 기준 **병합**(중복 건너뜀, 덮어쓰기 아님) → 완료 후 개수 표시.
- **백업 상기**: 마지막 백업 14일 경과 시 홈 하단에 작은 배너 1줄 (끌 수 있음).
- **프라이버시**: 사진·백업 파일은 git에 절대 올리지 않음 (`.gitignore`에 `*.zip`, `private-data/` 등록).

## 7. 폴더 구조 (예정)
```
mealsnap/
├─ README.md
├─ docs/PLAN.md          # 이 문서
├─ index.html            # 앱 진입점
├─ manifest.webmanifest
├─ service-worker.js     # 오프라인 캐시
├─ icons/
└─ src/
   ├─ db.js              # IndexedDB 래퍼 (meals, settings)
   ├─ image.js           # 리사이즈·썸네일·EXIF 시각 추출
   ├─ camera.js          # 촬영/갤러리 가져오기
   ├─ backup.js          # ZIP 작성·읽기, 병합
   ├─ views/calendar.js
   ├─ views/day.js
   ├─ views/timeline.js
   ├─ views/viewer.js
   └─ app.js             # 라우팅(해시), 하단 촬영 버튼
```

## 8. 개발 단계
| 단계 | 내용 | 완료 기준 |
|---|---|---|
| M0 | 뼈대: PWA 설정, 해시 라우팅, 하단 촬영 버튼 | 폰에 설치되고 빈 화면 3개 이동 |
| M1 | 촬영 → 축소 → IndexedDB 저장 → 하루 화면 | 찍으면 오늘 목록에 시각과 함께 뜸 |
| M2 | 달력 + 날짜별 횟수 표시 | 날짜 탭 → 하루 화면 |
| M3 | 타임라인 + 사진 뷰어(스와이프) | 전체 기록을 연속으로 넘겨봄 |
| M4 | 백업/복원, 삭제, 시간 수정, 갤러리 추가 | 백업 → 데이터 삭제 → 복원 시 동일 |
| M5 | 마감: persist 요청, 오류 안내, 아이콘, 성능(1만 장 스크롤) | 1만 장에서도 스크롤 부드러움 |

## 9. 결정이 필요한 것
1. **기기**: iPhone / Android 어느 쪽? (iOS면 PWA 저장 정책과 백업이 더 중요해짐)
2. **PWA로 시작**해도 괜찮은지 (권장) vs 처음부터 네이티브
3. **이 저장소 안의 `mealsnap/` 폴더**로 진행할지, 별도 GitHub 저장소로 분리할지 (현재는 기존 저장소 안의 독립 폴더로 시작)
4. 사진 보관 해상도 — 기본 긴 변 1280px (더 크게 원하면 용량 증가)
5. 앱 잠금(PIN) 필요 여부
